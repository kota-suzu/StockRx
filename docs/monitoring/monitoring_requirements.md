# StockRx モニタリング・分析機能要件定義書

## 1. 概要

StockRxシステムの包括的なモニタリング・分析機能を実装し、システムの健全性と業務パフォーマンスを可視化する。

## 2. アラート要件

### 2.1 業務アラート

#### 在庫管理アラート
- **低在庫アラート**
  - 条件: 在庫数が安全在庫レベル以下
  - 優先度: 高
  - 通知先: 店舗管理者、該当店舗スタッフ
  - 通知方法: リアルタイム通知、メール（オプション）

- **在庫切れアラート**
  - 条件: 在庫数が0
  - 優先度: 緊急
  - 通知先: 全管理者、該当店舗マネージャー
  - 通知方法: リアルタイム通知、メール、SMS（将来）

- **期限切れアラート**
  - 条件: バッチ期限切れまで30日以内
  - 優先度: 中～高（残日数による）
  - 通知先: 品質管理責任者、店舗スタッフ
  - 通知方法: 日次バッチ、リアルタイム通知

#### 店舗間移動アラート
- **移動申請承認待ち**
  - 条件: 24時間以上未承認
  - 優先度: 中
  - 通知先: 承認権限者
  - エスカレーション: 48時間で上位管理者へ

### 2.2 システムアラート

#### パフォーマンスアラート
- **レスポンスタイム遅延**
  - 閾値: 平均200ms以上（95パーセンタイル: 500ms）
  - 優先度: 高
  - 通知先: システム管理者、DevOpsチーム

- **メモリ使用率**
  - 閾値: 80%以上で警告、90%以上で緊急
  - 優先度: 高～緊急
  - 自動対応: 90%でワーカー再起動

- **Sidekiqキュー遅延**
  - 閾値: 100件以上のキュー滞留
  - 優先度: 中
  - 対応: 自動スケーリング検討

#### セキュリティアラート
- **不正アクセス検知**
  - 条件: SecurityMonitorで異常パターン検出
  - 優先度: 緊急
  - 通知先: セキュリティチーム、システム管理者
  - 自動対応: IP自動ブロック

- **大量ログイン失敗**
  - 閾値: 5回/IPアドレス
  - 優先度: 高
  - 自動対応: 15分間アカウントロック

#### エラーアラート
- **ジョブ失敗率**
  - 閾値: 5%以上の失敗率
  - 優先度: 中～高
  - 通知先: 開発チーム

- **CSVインポートエラー**
  - 条件: インポート失敗
  - 優先度: 高
  - 通知先: データ管理者、アップロードユーザー

### 2.3 アラート配信設定

#### 通知チャンネル
1. **リアルタイム通知**: ActionCable（実装済み）
2. **メール通知**: AdminMailer（部分実装）
3. **Slack/Teams**: Webhook連携（未実装）
4. **SMS**: 緊急時のみ（未実装）

#### エスカレーション設定
```
Level 1 (初回): 担当者へ通知
Level 2 (1時間後): チームリーダーへ通知
Level 3 (4時間後): 管理者へ通知
Level 4 (24時間後): 経営層へ通知
```

## 3. ダッシュボード要件

### 3.1 総合監視ダッシュボード

#### リアルタイムメトリクス
- **システムヘルス**
  - サーバー稼働率
  - レスポンスタイム（平均、95%ile）
  - エラー率
  - アクティブユーザー数

- **インフラメトリクス**
  - CPU使用率
  - メモリ使用率
  - ディスク使用率
  - ネットワークI/O

- **アプリケーションメトリクス**
  - リクエスト数/分
  - データベースクエリ時間
  - キャッシュヒット率
  - Sidekiqジョブ統計

### 3.2 業務ダッシュボード

#### 在庫管理ダッシュボード
- **在庫サマリー**
  - 総在庫価値（リアルタイム）
  - カテゴリ別在庫分布
  - 低在庫/在庫切れ商品数
  - 在庫回転率

- **在庫トレンド**
  - 日次/週次/月次在庫推移
  - 入出庫履歴グラフ
  - 季節性分析

- **アラート状況**
  - アクティブアラート一覧
  - アラート発生トレンド
  - 対応状況

#### 店舗パフォーマンスダッシュボード
- **店舗別KPI**
  - 在庫価値ランキング
  - 在庫効率性（在庫回転率）
  - 移動申請処理時間

- **比較分析**
  - 店舗間パフォーマンス比較
  - 前期比較（YoY、MoM）
  - ベンチマーク表示

### 3.3 セキュリティダッシュボード

- **アクセス監視**
  - アクセス元IP分布（地図表示）
  - 異常アクセスパターン
  - ブロックリスト状況

- **認証状況**
  - ログイン成功/失敗率
  - アカウントロック状況
  - 権限別アクセス統計

### 3.4 運用ダッシュボード

- **ジョブ実行状況**
  - Sidekiqキュー状況
  - ジョブ成功/失敗率
  - 実行時間分布
  - スケジュールジョブ状況

- **データ品質**
  - CSVインポート成功率
  - データ整合性チェック結果
  - マスターデータ更新履歴

## 4. 技術要件

### 4.1 データ収集

- **メトリクス収集間隔**
  - リアルタイム: 1秒（WebSocket）
  - 集計データ: 1分
  - 統計データ: 5分

- **データ保持期間**
  - 生データ: 7日間
  - 集計データ: 90日間
  - 統計データ: 2年間

### 4.2 パフォーマンス要件

- ダッシュボード初期表示: 2秒以内
- リアルタイム更新遅延: 100ms以内
- 同時接続数: 100ユーザー以上

### 4.3 可用性要件

- ダッシュボードSLA: 99.5%
- データ欠損率: 0.1%未満
- 障害時自動フェイルオーバー

## 5. 実装優先順位

### Phase 1（必須）
1. アプリケーションメトリクス基盤構築
2. 基本的なアラート機能（在庫、エラー）
3. シンプルな監視ダッシュボード

### Phase 2（重要）
1. 業務KPIダッシュボード
2. 高度なアラート設定（エスカレーション）
3. Sidekiqジョブ監視強化

### Phase 3（推奨）
1. 予測分析機能
2. 外部通知連携（Slack等）
3. カスタマイズ可能なダッシュボード

## 6. 成功指標

- アラート対応時間: 30分以内（95%）
- 誤検知率: 5%未満
- ダッシュボード利用率: 80%以上
- システム障害の事前検知率: 70%以上
